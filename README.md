# Fedora + AmneziaVPN: раздача VPN через Wi-Fi

Настройка раздачи VPN с Fedora на LG webOS, телефон и другие устройства.
Fedora получает интернет по Ethernet, подключается через AmneziaVPN
и раздаёт соединение отдельным Wi-Fi-адаптером.

Поддерживаются два проверенных варианта VPN-интерфейса:

- `amn0` — прежняя конфигурация AmneziaWG 2;
- `tun2` — текущая конфигурация AmneziaVPN, раздача восстановлена 29.09.2026.

Имя `tun2` само по себе не определяет протокол VPN. Протокол выбирается
в AmneziaVPN, а фактический интерфейс проверяется по маршруту.

## Схема и параметры

```text
Интернет → Ethernet enp4s0 → Fedora / AmneziaVPN
                                 │
                         VPN: amn0 или tun2
                                 │
                         IPv4 forwarding + NAT
                         разрешения DOCKER-USER
                                 │
                         Wi-Fi wlp8s0f3u4u4
                         профиль Home-WiFi
                         сеть 10.42.0.0/24
                                 │
                         LG webOS / телефон
```

| Параметр | Значение |
|---|---|
| ОС | Fedora; последнее исправление проверено на Fedora 44 |
| Основной интернет | Ethernet `enp4s0` |
| VPN | AmneziaVPN, интерфейс `amn0` или `tun2` |
| Wi-Fi-адаптер | `wlp8s0f3u4u4` |
| Профиль NetworkManager | `Home-WiFi` |
| SSID в примерах | `MyHotspot` — замените своим |
| Режим Wi-Fi / IPv4 | `ap` / `shared` |
| Адрес Fedora в Wi-Fi | `10.42.0.1/24` |
| Подсеть клиентов | `10.42.0.0/24` |
| Правила пересылки | `iptables`, цепочка `DOCKER-USER` |
| Автозапуск правил | `lg-vpn-share.service` |

Имена интерфейсов и подсеть на другом компьютере могут отличаться.
Проверьте их перед использованием команд и скрипта. Пароль Wi-Fi,
конфигурация VPN и приватные ключи в репозитории не хранятся.

## 1. Проверить предварительные условия

Нужны рабочий Ethernet, установленный и настроенный AmneziaVPN,
NetworkManager, Wi-Fi-адаптер с поддержкой AP и права администратора.
Эта инструкция рассчитана на Docker с существующей цепочкой `DOCKER-USER`.
Если её нет, остановитесь и проверьте используемый firewall; не создавайте
цепочку вручную и не меняйте backend Docker ради этой инструкции.

```bash
nmcli device status
ip -br address
nmcli -f WIFI-PROPERTIES.AP device show wlp8s0f3u4u4
sudo iptables -S DOCKER-USER
```

Ожидается `WIFI-PROPERTIES.AP: yes`.

## 2. Подключить VPN и определить интерфейс

Подключите нужный профиль в AmneziaVPN. Его установка и VPN-конфигурация
не входят в этот репозиторий.

```bash
ip -br address
ip -4 route get 1.1.1.1
```

Для описанной схемы ожидается `dev amn0` или `dev tun2`. Если маршрут
использует другой интерфейс, сначала выясните причину. Скрипт не выбирает
VPN, не подключает его и не меняет маршруты.

## 3. Создать точку доступа — только при отсутствии профиля

Сначала проверьте, существует ли профиль:

```bash
nmcli connection show Home-WiFi
```

**Если профиль существует, пропустите создание.** Не удаляйте и не
пересоздавайте его при диагностике отсутствующего интернета.

Если профиля нет, выполните в Bash:

```bash
sudo nmcli radio wifi on
read -rsp "Пароль новой Wi-Fi-сети: " WIFI_PASSWORD
echo
sudo nmcli device wifi hotspot \
  ifname wlp8s0f3u4u4 \
  con-name Home-WiFi \
  ssid MyHotspot \
  password "$WIFI_PASSWORD"
unset WIFI_PASSWORD
```

Замените `MyHotspot` своим SSID. Используйте пароль длиной не менее
8 символов и не сохраняйте его в репозитории.

## 4. Проверить профиль и включить автоподключение

```bash
nmcli -f connection.id,connection.interface-name,connection.autoconnect,802-11-wireless.mode,ipv4.method connection show Home-WiFi
```

Ожидаются интерфейс `wlp8s0f3u4u4`, режим `ap` и `ipv4.method: shared`.

```bash
sudo nmcli connection modify Home-WiFi connection.autoconnect yes
```

Если профиль ещё не активен, запустите его:

```bash
sudo nmcli connection up Home-WiFi ifname wlp8s0f3u4u4
```

```bash
nmcli device status
ip -4 address show wlp8s0f3u4u4
```

В проверенной конфигурации адрес точки доступа — `10.42.0.1/24`.
Если NetworkManager выбрал другую подсеть, согласуйте адреса и правила
скрипта перед установкой. Режим `shared` обеспечивает DHCP и NAT.

## 5. Проверить пересылку и маршрут клиента

```bash
sysctl net.ipv4.ip_forward
ip -4 route get 1.1.1.1 from 10.42.0.2 iif wlp8s0f3u4u4
```

Ожидаются `net.ipv4.ip_forward = 1` и маршрут через текущий VPN-интерфейс.
`10.42.0.2` — пример адреса клиента; можно подставить адрес телефона.
Если пересылка выключена, проверьте активацию профиля с методом `shared`.
При необходимости включите её для текущего сеанса:

```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

NAT для `10.42.0.0/24` в проверенной системе создаёт NetworkManager
в nftables. Скрипт раздачи дополнительных правил NAT не добавляет.

## 6. Установить правила раздачи

В проверенной системе цепочка `FORWARD` имеет политику `DROP`.
Скрипт добавляет в `DOCKER-USER` по два разрешения для `amn0` и `tun2`:

| Вход → выход | Ограничение |
|---|---|
| Wi-Fi → `amn0` | Источник `10.42.0.0/24` |
| `amn0` → Wi-Fi | Получатель `10.42.0.0/24`, `ESTABLISHED,RELATED` |
| Wi-Fi → `tun2` | Источник `10.42.0.0/24` |
| `tun2` → Wi-Fi | Получатель `10.42.0.0/24`, `ESTABLISHED,RELATED` |

Выполните из корня репозитория. При обновлении сначала сохраните копию
установленного скрипта:

```bash
if sudo test -f /usr/local/sbin/lg-vpn-share.sh; then
  sudo cp -a /usr/local/sbin/lg-vpn-share.sh \
    "/usr/local/sbin/lg-vpn-share.sh.backup-$(date +%Y%m%d-%H%M%S)"
fi
sudo install -m 755 scripts/lg-vpn-share.sh /usr/local/sbin/lg-vpn-share.sh
sudo /usr/local/sbin/lg-vpn-share.sh
sudo iptables -nvL DOCKER-USER --line-numbers
```

Скрипт проверяет наличие каждого правила перед добавлением. Повторный
запуск не создаёт дубликаты. Порядок четырёх правил может зависеть
от предыдущих запусков; счётчики растут у пары активного VPN-интерфейса.
Нулевые счётчики у отсутствующего `amn0` при работе через `tun2` нормальны.

Скрипт не очищает цепочки, не меняет общую политику `FORWARD` и
не перезапускает Docker или контейнеры. Правила для Ethernet он не добавляет.

## 7. Настроить автозапуск

```bash
sudo install -m 644 systemd/lg-vpn-share.service \
  /etc/systemd/system/lg-vpn-share.service
sudo systemctl daemon-reload
sudo systemctl enable --now lg-vpn-share.service
```

При обновлении уже активной службы примените новый скрипт явно:

```bash
sudo systemctl restart lg-vpn-share.service
```

`enable --now` не выполняет заново уже активную службу. Перезапуск
`lg-vpn-share.service` применяет правила; Docker при этом не перезапускается.

```bash
systemctl status lg-vpn-share.service --no-pager
sudo iptables -nvL DOCKER-USER --line-numbers
```

Для одноразовой службы нормальны `active (exited)` и `status=0/SUCCESS`.
Это означает успешный запуск скрипта, а не наличие VPN или доступность
интернета. Служба запускается после Docker и NetworkManager и может
установить правила ещё до появления VPN-интерфейса.

## 8. Проверить результат на клиенте

1. Подключите телефон или LG к своему SSID.
2. На телефоне отключите мобильные данные на время проверки.
3. Откройте сайт и проверьте рост счётчиков правил активного интерфейса.
4. Проверьте внешний IP на самом клиенте и сравните с ожидаемым IP VPN.

```bash
sudo iptables -nvL DOCKER-USER --line-numbers
```

29.09.2026 подтверждены передача трафика через `tun2` в обе стороны
и восстановление интернета пользователем. Все семь Docker-контейнеров
продолжали работать. Профиль Wi-Fi не пересоздавался. Проверка внешнего
IP клиента в ходе этого исправления отдельно не выполнялась.

После следующей плановой перезагрузки проверьте профиль, службу, маршрут
и счётчики теми же командами. Если AmneziaVPN не подключается автоматически,
подключите его вручную. **Полный цикл перезагрузки после исправления
ещё не проверен.**

## Диагностика и ограничения

Порядок безопасной диагностики и разбор сбоя из-за смены `amn0` на `tun2`:
[docs/troubleshooting.md](docs/troubleshooting.md).

- Поддерживаются именно интерфейсы `amn0` и `tun2`. При изменении их имён
  нужно сначала проверить маршрут и назначение нового интерфейса.
- Если Docker или firewall удалит правила, их потребуется применить снова.
  Служба не отслеживает такие изменения непрерывно.
- Разделение трафика по сайтам в AmneziaVPN не проверено для клиентов Wi-Fi.
  Эти правила не гарантируют работу исключений для видеосервисов и
  не являются самостоятельной гарантией блокировки всех утечек вне VPN.
- Компьютер и VPN должны оставаться включёнными.
